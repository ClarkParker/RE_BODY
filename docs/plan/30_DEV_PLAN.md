# 30 — Development plan RE·BODY v1

## 0. Ground rules
- Language: repository, documentation, code comments, plugin strings in English. Chat with the owner in German.
- **Concept freeze before code:** no DSP or UI source is written until the owner has approved `docs/concept/20`, `21`, `22` and this plan.
- Branches: this repo on `claude/gallant-mendel-xg901g`. Rules and recipes from the **newest** DEV-Kit branch `claude/vibrant-faraday-cmymob` (b4e7021, 2026-09-26: upstream-synced param binding, `.patch-root`, lint rules, `docs/07_SCALING.md`, `ai/amorph_official/CORE_*.md`), plus `docs/15_BRANDING.md` from `9ce8d6d`. Upstream authority `amorph-for-agents` (d84ae4e; canonical aece339 differs only by the Cmajor pin 1.0.3209). Re-check for newer branches at the start of every phase.
- Branding (owner decision): manifest `manufacturer = "CLΞΛRPΞΛK"` (raw UTF-8, Greek Ξ U+039E and Λ U+039B), UI shows the brand small, left-aligned, directly under the plugin name (15_BRANDING §1-2). Plugin name `RE·BODY`, identifier `RE_BODY`, ID `com.clearpeak.re_body` (ASCII), description credits "based on BODY by Artists in DSP".
- Kit rule 8: a kit recipe is adopted verbatim the first time (07_SCALING, 03 echo guard, 04 bypass rule, 06 oversampling if ever needed, 12 testing), then diffed line by line; every deviation is written down (e.g. 07 zoom chassis vs upstream fluid layout).
- Verification before every push: `preflight.py --strict`, `manifest_check.py --strict`, `cmaj generate`/`cmaj test`/`cmaj render` (compiler via `tools/get_cmaj.sh`, version from the kit pin), plus the manual checks the lint lacks (`let`, `Math.`, `skew`, `data-param` uniqueness). Verified intermediate states are committed and pushed immediately (kit rule 6).
- Live Amorph checks (`run_qa_probe`, `run_ui_probe`, `audition_patch`) can only run on the owner's machine: hand-over is always repo + branch + path (kit rule 4), never files.
- Reporting (kit rule 7): after each phase an explicit completion report, item by item, with the location in the repo or UI.
- Models: Fable for design decisions, reviews and integration; Opus for DSP maths that must be right the first time; Sonnet for code generation from a fixed spec, tooling and tests; Haiku for mechanical passes (renames, table emission checks, inventories).

## 3. Risks and mitigations
| Risk | Mitigation |
|---|---|
| Table emission: large literals may fail (Cmajor #135), manifest `externals` unverified in Amorph | P1 tries all three forms (each form tried, at least one clean, chosen form documented); tables chunked per body |
| `cmaj` download in the cloud container (proxy) | `tools/get_cmaj.sh` with the kit pin; fallback: owner runs the gate locally and reports |
| Re-coupling the hybrid after Oboe gets cluster + formant modes (no cone in v1) and Uke/Sax get real bodies | Keep BODY's injection points and constants as defaults; render-compare the end stop against the original |
| Loudness drift when 2-10 modes become a 96-pole grid plus per-body slots | BODY's loudness stage inside every line, energy normalisation per slot body, grid normalisation cached per Size/Material/Decay, re-measured `out_gain`; protector unchanged; gates: Line A within ±1.5 dB LUFS of the original, protector reduction < 3 dB with three lines (T2) |
| Pointer events not delivered in DAW WebViews | Idle and audio motion sources make depth visible without a pointer; pointermove delivery recorded in the P1 spike, confirmed in P7 |
| 19 compositing layers (preserve-3d worst case) in WebView2/WebKit | Render budget (N12): ≤ 12 layers (fittings and strings merged), vibration on ≤ 3 layers at 30 Hz, light as a moved pre-painted layer; frame-time budget ≤4 ms measured in the host WebView in the P1 spike, headless in P6, in host in P7 |
| CPU unknown | Target note, not a ceiling: ≤ 8 % of one core at 96 kHz for three lines, measured in P7; `float<8>` SIMD lanes for the modal banks, updates only for bodies with weight > 0 or ringing tails, gating at −120 dB relative, control-rate maths; pitch tracker runs only while Follow > 0 |
| 73 parameters overwhelm the panel | Only the active line's set is visible; strips collapsible; defaults make Line A alone behave like BODY |
| ≈184 k floats of line state with 4096-sample buffers (three lines; 381 k with BODY's buffer sizes) risk a host compile stall (core-dsp guidance 131072 floats; struct-array bug #94) | 4096-sample delay buffers (C2 at 96 kHz = 1468 samples, Follow floor 40 Hz = 2400; piano pair 8192) + one shared string engine per line for Guitar/Ukulele/Fiddle; full-size `struct Line` × 3 and measured compile time in the P1 spike; fallback per-line members or three processor nodes |
| Hidden controls (inactive lines, MORE) may fail the `run_ui_probe` visibility audit | P1 spike records the probe; fallback: compact always-visible strip for lines B and C instead of tabs, Classic as a skin that hides nothing (owner questions Q3, Q5) |
